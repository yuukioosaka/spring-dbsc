Signed in as user

1. Unguarded route

Answers with a valid login cookie alone — this is what a stolen cookie replays.




2. Guarded route



    Requires a fresh per-request proof signed by the device key, bound to the body.
    With no proof it is 403, never 401 — Chromium treats 401 on
    these paths as fatal.











3. Bound / polyfill client (spec 03)



    The native path above needs no JavaScript. bound does: it is the
    dbsc-toolkit
    Web Crypto polyfill, loaded here from /dbsc-client/index.js. Its key
    lives in IndexedDB, so it is readable by page script — weaker than
    a native key, see the README's "Native vs. polyfill" section.




    initBoundDbsc() reads /dbsc-bound/state and, if the server
    asks for it, registers a polyfill key. wrapFetch() then signs
    individual requests with X-Dbsc-Bound-Proof, which is what the
    guarded route below accepts.
